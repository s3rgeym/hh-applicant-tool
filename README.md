## Описание

> [!IMPORTANT]
> Tool — утилита, это программа не имеющая GUI/TUI, те данное ПО задумывалось
> строго для работы в сосноли/терминале, а поэтому все ее гуевые фишки
> существуют постольку-поскольку (Alacritty не поддерживает вывод графики).
> Её предназначение крутиться где-то в автозапуске, не отвлекая на себя
> внимание. Написал раз конфиг, запустил и забыл.

С появлением нейронок первыми решили автоматизировать самых бесполезных сотрудников в любой компании — овчаров, а тут ещё война, санкции, кризис, сокращения, и всё это легло на хроническую некомпетентность отечественных самозваных эксперт_ок, которые все, судя по их профилям, еще психологини, тарологини, нутриологи (ага, разводят нутрий)... В итоге поиск работы превратился в ад. В худшем случае нужно: 1) пройти тесты с 20-40 вопросами, 2) написать там целый рассказ о себе, 3) ответить на вопросы аналоговнетного хуИИ-рекрутёра в чате после отклика, после чего он подключит к чату «специалистку» по просмотрам резюме, 4) ответить на вопросы этой «царица во дворца» (чтобы потом в итоге вас все равно оценил ChatGPT). Всё это умеет автоматизировать данная утилита, если руки растут из нужного места, а вот следующие 10 этапов с лайвкодингом и квадробингом, увы, нет...

Функционал и особенности:

- 🐍 Утилита написана на Python, а значит может быть запущена на любой системе, куда его можно установить (Windows, Linux, Mac и даже на Android)
- 🤖 Поддержка ИИ (ChatGPT, Claude и все что работает через OpenAI API Specification)
- 🔄 Авто-поднятие резюме
- 📤 Рассылка откликов с генерацией сопроводительных и решением тестов (может работать без нейронки)
- 🧩 Автоматическое распознание капчи
- 📧 Дополнительная рассылка писем на Email работодателям с просьбой рассмотреть резюме
- 💬 Автоответчик в чате с работодателем с ответом на вопросы (если при отклике нет теста, то тест гарантированно будет в чате) в тч с вариантами (кнопки)
- 👥 Поддержка нескольких аккаунтов через профили
- 🛡️ Запуск прямо с вашего устройства с эмуляцией работы через браузер и официальное Android-приложение (в headless-режиме он не запускается, используется лишь "стандартная" библиотека `requests` для всех запросов). Для HH вы выглядите как обычный пользователь, что сводит к минимуму риск блокировки (в отличие от сторонних веб-сервисов, чьи аккаунты быстро банят)
- 🔒 Данные хранятся локально, никаких скрытых зондов и отправки данных на сторонние сервера, а значит ваши данные не утекут в результате взлома или не будут переданы различным мошенникам
- ⚙️ В отличии от различных сервисов и других решений, все промпты можно прописать самому в конфиге. Универсальных решений не бывает, а однотипные сервисные ответы палятся как уши зайца, торчащие из кустов...
- 🖥️ Может запускаться на сервере. В отличии от сторонних реализаций не использует Headless Chromium, поэтому потребляет минимальное количество ресурсов, что критично для бюджетных серверов. Хромиум сильно грузит процессор, потребляет сотни мегабайт оперативной памяти при открытии hh и требует 1-2 гигабайт свободного места. Так что утилите хватит и VDS за пару сотен.
- 📖 Открытый исходный код

## Установка

Утилиту можно установить из `PyPi` или скачать из репозитория. Из остальных мест ее скачивать не рекомендуется.

Установка:

```bash
# Стандартный pip (в Linux только в виртуальное окружение получится установить)
$ pip install hh-applicant-tool

# Но лучше использовать pipx
$ pipx install hh-applicant-tool

# Последнюю версию можно установить через git
$ pipx install "git+https://github.com/s3rgeym/hh-applicant-tool"

# Для обновления до новой версии
$ pipx upgrade hh-applicant-tool
```

pipx добавляет исполняемый файл `hh-applicant-tool` в `~/.local/bin`, делая эту команду доступной. Путь до `~/.local/bin` должен быть в `$PATH` (в большинстве дистрибутивов он добавлен).

Использование виртуальных окружений в Linux/Mac:

```sh
mkdir -p ~/.venvs
python -m venv ~/.venvs/hh-applicant-tool
# Это придется делать постоянно, чтобы команда hh-applicant-tool стала доступна
.  ~/.venvs/hh-applicant-tool/bin/activate
pip install hh-applicant-tool
```

Пользователям Linux/MacOS нужно установить `tkinter` для поддержки gui-шных всплывающих окон для ввода капчи. В Windows он ставится с питоном.

Отдельно я распишу процесс установки в **Windows** в подробностях:

- Для начала поставьте последнюю версию **Python 3** любым удобным способом.
- Запустите **PowerShell** (не `CMD.EXE`, блять, а именно поверщель) от Администратора и выполните:

  ```ps
  Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy Unrestricted
  ```

  Данная политика разрешает текущему пользователю (от которого зашли) запускать скрипты. Без нее не будут работать виртуальные окружения.

Далее можно поставить `pipx` и вернуться к инструкции вверху раздела:

- Всё так же от администратора выполните:

  ```ps
  python -m pip install --user pipx
  ```

  А затем:

  ```ps
  python -m pipx ensurepath
  ```

- Перезапускаем Terminal/Powershell и проверяем:

  ```ps
  pipx -h
  ```

С использованием вирт. окружений:

- Создайте и активируйте виртуальное окружение:

  ```ps
  PS> python -m venv hh-applicant-venv
  PS> .\hh-applicant-venv\Scripts\activate
  ```

- Поставьте все пакеты в виртуальное окружение `hh-applicant-venv`:

  ```ps
  (hh-applicant-venv) PS> pip install hh-applicant-tool
  ```

- Проверьте, работает ли оно:

  ```ps
  (hh-applicant-venv) PS> hh-applicant-tool -h
  ```

- В случае неудачи вернитесь к первому шагу.
- Для последующих запусков сначала активируйте виртуальное окружение.

## Авторизация

Авторизация по коду:

```bash
$ hh-applicant-tool authorize 79012345678
📱 Введите полученный код из SMS: 1488
🎉 Авторизация прошла успешно!
```

Если при авторизации указать email, то код придет на него.

Для авторизации по паролю передайте вторым аргументом пароль (после регистрации его нужно установить).

> Если у вас есть еще профиль работодятла или овчара, то тип авторизации
> принудительно будет сменен на соискателя (applicant)

Проверка авторизации:

```bash
$ hh-applicant-tool whoami
🆔 27405918 Кузнецов Андрей Владимирович [ 📄 1 | 👁️ +115 | ✉️ +28 ]
```

В случае успешной авторизации токены будут сохранены в [token.json](#tokenjson):

```json
{"token":{"access_token":"USER7K2QX9MZ4TBW8LRN3VYD6HJ5CFA1GEP0UXSO7IQKZ2WMT9BNL4RYV8DHC3JF","refresh_token":"USERX4PN8QWZ1KDT6VHB3MRJ9YLC2FGS5UEA7OIX0NBQ4WTZ8KMV1DPH6RJC3YLF","access_expires_at":1798765432}}
```

Токен доступа выдается на две недели. <s>Для его обновления нужно выполнить:

```bash
hh-applicant-tool refresh-token
```

</s> Он обновляется автоматически.

Помните, что у `refresh_token` тоже есть время жизни, поэтому может потребоваться полная авторизация, если долго не запускать утилиту + время жизни cookies может быть меньше времени жизни токенов, поэтому часть функционала, требующая авторизации на сайте может отваливаться, поэтому в любой непонятной ситуации следует попробовать авторизоваться по-новой.

## Описание команд

Примеры команд:

```bash
# Общий вид команды
$ hh-applicant-tool [глобальные флаги] [операция] [флаги самой операции]


# Справка по глобальным флагам и список операций
$ hh-applicant-tool -h

# Справка по операции
$ hh-applicant-tool authorize -h

# Авторизация по одноразовому коду, где username — телефон или email
$ hh-applicant-tool authorize <username>

# Авторизация по паролю
$ hh-applicant-tool authorize <username> <password>

# Авторизация с использованием другого профиля
# В дальнейшем для вызова всех операций надо профиль передавать,
# либо установить переменную окружения
$ hh-applicant-tool --profile profile123 authorize

# Рассылаем отклики
$ hh-applicant-tool apply-vacancies

# Для тестирования поисковой строки и других параметров, используйте --dry-run.
# С ним отклики не отправляются, а лишь выводятся сообщения
# При тестировании надо выводить как можно меньше вакансий, так как есть лимит на 2000 показанных вакансий в сутки
# -vv выводят все запросы и прочую отладочную информацию для диагностирования ошибок
$ hh-applicant-tool -vv apply-vacancies --search "Python разработчик" --total-pages 1 --per-page 3 --dry-run

# Фильтруем вакансии по исключаемым словам с помощью регулярки (fullstack, junior, php и т.п.)
# Вакансии, не прошедшие фильтр, добавляются в черный список
# см hh.ru/applicant/blacklist/vacancy?hhtmFrom=main&hhtmFromLabel=header
# Работает очень быстро, но пропускает всякий мусор (пояснение см далее)
$ hh-applicant-tool apply-vacancies --search "Python Backend" --excluded-filter "fullstack|junior|php|java"

# То же самое, но с использованием нейронки (работает очень медленно)
# Если не переписывать шаблоны промпта, то будет сравнивать вакансию с названием резюме и ключевыми навыками,
# указанными в нем. Этого хватает чтобы исключить курьеров и преподавателей онлайн-школ.
# На хх просто есть услуга продвижения вакансий, и когда сайту их показать некому, он начинает их вставлять
# в результаты поиска, типа а вдруг заинтересует...
$ hh-applicant-tool apply-vacancies --search "Python Backend" --filter-ai

# Поднимаем резюме
$ hh-applicant-tool update-resumes

# Запускаем автоответчик в чате (если настроен openai)
$ hh-applicant-tool reply-chats --loop

# Чистим отказы в откликах (не имеет особого смысла, так как автоответчик при отказе покидает чат, и тот больше не мозолит глаза)
# Может дополнительно забанить работодателей за отказы или мог. Кандидат к переписанию
$ hh-applicant-tool clear-negotiations

# Проверка доступных обновлений
$ hh-applicant-tool check-updates
🚀 Доступна новая версия: 2.3.4 (у вас 2.3.3)
📦 Обновить: pip install -U hh-applicant-tool

# Просмотр лога в реальном времени
$ hh-applicant-tool log -f

# Редактировать конфиг в стандартном редакторе
$ hh-applicant-tool config -e

# Установить значение в конфиге, например, socks-прокси
# УЧТИТЕ, ЧТО ПРИ ТАКОМ СПОСОБЕ ИЗМЕНЕНИЯ КОНФИГА, ИСЧЕЗНУТ ВСЕ КОММЕНТАРИИ В НЕМ!!!
$ hh-applicant-tool config openai.default.proxy_url socks5h://localhost:1080

# Вывести значение из конфига
$ hh-applicant-tool config openai.default.proxy_url

# Удалить значение из конфига
# Эта операция тоже форматирует конфиг, удаляя из него комментарии
$ hh-applicant-tool config -d openai.default.proxy_url
```

AI (ChatGPT и тп) будет использоваться автоматически, если в [конфиге](#конфигурационный-файл) заданы настройки для `openai`.

Глобальные флаги:

| Флаг                      | Описание                                                                                                                                           |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `-v`                      | используется для вывода отладочной информации. Два таких флага, например, выводят запросы к **API**.                                               |
| `-c <path>`               | путь до каталога, где хранятся конфигурации.                                                                                                       |
| `--profile <profile-id>`  | можно указать профиль, данные которого будут храниться в подкаталоге.                                                                              |
| `--use-kitty/--use-sixel` | использовать опр протокол для отображения капчи в терминале. Если не указывать, то капча будет отображена через `tkinter`, если тот установлен.... |
| `--no-use-ai/--no-ai`     | игнорировать настройки AI в конфиге.                                                                                                               |

> `--ai/--use-ai` теперь используются по дефолту, поэтому их указывать не надо

Доступные операции (имеют свои флаги, название операции идет после флагов самого hh-applicant-tool):

| Операция                       | Описание                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `authorize`, `auth`, `login`   | Авторизация на hh.ru. Введенный логин "запоминается" и будет использован при следующем вызове команды. Раньше, когда авторизация запускалась через браузер, была авторизация и по паролю, но когда я переписал авторизацию без использования браузеров мне тупо лень делать еще и по паролю. Там просто капча другим способом обрабатывается, поэтому авторизация будет только по коду, пока кто-нибудь другой не подсуетится |
| `logout`                       | Выйти из профиля на сайте и из приложения                                                                                                                                                                                                                                                                                                                                                                                     |
| `whoami`, `id`                 | Выводит информацию об авторизованном пользователе. Используется для проверки не слетела ли авторизация                                                                                                                                                                                                                                                                                                                        |
| `list-resumes`, `list`, `ls`   | Список резюме                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `update-resumes`               | Обновить все резюме. Аналогично нажатию кнопки «Обновить дату».                                                                                                                                                                                                                                                                                                                                                               |

| **Linux**   | `~/.config/hh-applicant-tool/`                           |

### Конфигурационный файл

Конфигурационный файл называется `config.toml`. Он содержит основные настройки.

[TOML](https://ru.wikipedia.org/wiki/TOML) идеально подходит для хранения конфигураций, так как поддерживает мультистроки и комментарии в отличии от старого формата JSON, который разве что для роботов подходит.

Самый быстрый способ открыть конфиг в стандартном редакторе:

```bash
hh-applicant-tool config -e
```

Путь до него можно найти так:

```bash
hh-applicant-tool config -p

# Можно сразу открыть в любимом редакторе
code $(hh-applicant-tool config -p)
```

Практически все настройки имеют дефолтное значение. 

Поэтому все работает из коробки, задавать десятки промптов не нужно.

Единственное, что нужно задать — это прописать настройки OpenAI (протокол обмена данными, через который работают нейронки).

Минимальный конфиг может выглядеть примерно так:

Некоторые настройки передаются как аргумент конструктора, поэтому если увидите сообщение типа этого:

```sh
TypeError: ApiClient.__init__() got an unexpected keyword argument 'timeoutt'
```

То это ошибка не в коде, не баг, а всего лишь опечатка в конфиге.

Параметр `delay` в секциях `[api_client]` и `[openai.*]` работает не так как все думают:

- Допустим, у нас `delay = 0.5`
- Например, со времени предыдущего запроса к API прошло 0.3 секунды, тожда мы ждем 0.2 секунды (0.5 - 0.3)
- Если же прошло больше этого времени, перед запросом ожидание не делается

Это универсальнее rate limit'ов, так как работать будет везде, а не только там, где можно друг pf другом пять запросов выполнить, а на 6 лимит сработает. Много где 5 запросов в секунду - это 5 запросов с задержкой до 200мс.

### token.json

Токены авторизации вынесены в отдельный конфиг, так как при программном сохранении конфига TOML, из того пропадают комментарии. Для хранения в JSON особых причин нет, TOML то же бы подошел, но так исторически сложилось...

### cookies.txt

В `cookies.txt` хранятся куки, установленные при авторизации на сайте. Они нужны
для решения тестов при отклике на вакансию. Не редактируйте этот файл вручную.

Операция `logout` не только затирает токены, но очищает `cookies.txt`.

### Логи

В `log.txt` всегда можно посмотреть подробную информацию об ошибках. В целях безопасности токены, идентификаторы резюме и т. п. затираются. Для просмотра логов используйте операцию `log`.

### Переменные окружения

Утилита читает следующие переменные окружения:

| Переменная                    | Описание                                                                                                                               |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `CONFIG_DIR`                  | Каталог, в котором хранятся данные приложения, вместо пути по умолчанию (см. «Данные приложения»). В Docker задаётся как `/app/config` |
| `HH_PROFILE_ID`               | Имя подкаталога-профиля внутри `CONFIG_DIR` (по умолчанию `.`). Позволяет держать несколько изолированных профилей                     |

Первые нужны для удобства в `Docker`. Последние — де факто стандарт.

Если вызов какого-то метода API генерирует ошибку капчи, то она перехватывается, а далее происходит следующее:

- при включенном и настроенном AI, если не передан дополнительно
  `--captcha-manual`, капча будет распознаваться нейронкой, причем модель должна быть с поддержкой vision (например, в `llama3:latest` ее нет)
- иначе:
  - капча отображается в терминале, если есть флаги `--use-kitty`/`--use-sixel` с именами используемых протоколов для отображения изображений (первый поддерживает даже Windows Terminal)
  - если не поддерживается графика, то капча принудительно выводится в терминал через `sixel`
  - в противном случае капча будет отображена через всплывающее окно `tkinter`.

Перехват капчи я сделал глобальным прямо как в их мобильном приложении, где они обработчик 403 ошибки с капчей сделали через intercept okhttp3 (напоминаю, что Java — говно), где они ловят ошибку и показывают капчу в webview. У меня только webview нет как и потрохов браузера...

Особенность API хх.сру является то, что при достижении некоторых лимитов, причем, у каждого эндпоинта они свои, или же, например, если ему не нравится user-agent (поэтому не меняйте дефолтный), он может на все попытки решить капчу отдавать 403, те не засчитывать правильные решения. Это сделано чтобы боты бесконечно сливали токены. Экспериментально установить лимиты сложно, потому как они постоянно меняются. Могу сказать лишь, что после авторизации стоит подождать минут 10-15 перед началом рассылки, или на первом же отклике выскочет капча.

Язык капчи можно сменить с помощью специального флага:

```sh
hh-applicant-tool --captcha-lang {RU,EN} <operation>
```

По дефолту установлен английский, тк он лучше распознается.

Через сетевые модели распознавать капчи — не лучшая идея. Это нарушает правила подобных сервисов.

Капчу хх.сру хорошо распознает `gemma-4-E2B`, которая запускается даже на ноутах со встройкой.

## Шаблоны сообщений

При откликах доступны сл плейсхолдеры (как это на русском?) шаблонов (актуальный список см в `apply-vacancies -h`):

- `%(vacancy_name)s`: Название вакансии.
- `%(vacancy_url)s`: Ссылка на вакансию.
- `%(employer_name)s`: Название работодателя.
- `%(first_name)s`: Имя пользователя.
- `%(last_name)s`: Фамилия пользователя.
- `%(email)s`: Email пользователя.
- `%(phone)s`: Телефон пользователя.
- `%(resume_title)s`: Название резюме.
- `%(resume_hash)s`: Идентификатор резюме.
- `%(resume_url)s`: Ссылка на резюме.
- И прочие: `%(resume_salary)s`, `%(resume_work_format)s`,
  `%(resume_education)`, `%(resume_city)`...

Например:

```
Меня заинтересовала ваша вакансия %(vacancy_name)s. Прошу рассмотреть мою кандидатуру. С уважением, %(first_name)s %(last_name)s.
```

Плейсхолдеры можно использовать в промптах.

И эти плейсхолдеры не универсальны...

У `reply-chats` из общих только те, что для резюме, да и то не везде...

> [!NOTE]
> Все возможные плейсхолдеры слишком долго перечислять, поэтому чтобы узнать
> какие плейсхолдеры принимает тот или иной шаблон, можете добавить туда
> какой-нибудь неправильный типа %(foo)s, в сообщении ошибки будут показаны все
> доступные

Вообще эта форма записи — это старые, добрые форматированные строки в Python до того как из C# притащили ASCII-вагины `{}`. С ними можно разное делать, например, `%(first_name).1s` выведет первую букву имени...

Символ процента, если хотите использовать его не для имен плейсхолдеров, надо удваивать типа `Увеличил конверсию 228%%`.

Также можно делать текст уникальным с помощью `{}`. Внутри них через `|` перечисляются варианты, один из которых будет случайно выбран:

```
Увольте того {идиота|придурка}, который придумал этот {тупой|сраный|дурацкий} вопрос.
```

В итоге получится что-то вроде:

```
Увольте того идиота, который придумал этот сраный вопрос.
```

`{}` могут быть вложенными.

# git clone ...

sudo docker build -t hh_applicant_tool \

Точно так же обстоят дела с решением капчи. **API** буквально нам предлагает открыть страницу с капчей в браузере, решить ее, а потом вызвать нужный метод **API** снова.

Сам сайт ХХ использует React. На каждой странице есть тег `<template id="HH-Lux-InitialState"></template>`. Внутри него заключен JSON `{"redirectConfig":....}`, в котором разделители заменены на HTML-сущности. В нем содержатся данные, необходимые для рендеринга страницы. Если нужно спарсить какие-то данные с веб-версии (у них она называется десктопной), то искать их стоит там. Там, кстати, много лишнего хранится: от ссылки на бота в Telegram для сотрудников поддержки сайт до страниц каких-то инфоцыган (этот уебанский сайт ставку сделал на зарабатывание денег на соискателях, я это осуждаю в отличии от доения тамошних работодятлов с их тупорылыми херками).

Сами эндпоинты сайта работают довольно странно. Параметры могут передавать через тело, Query String, через куки и заголовки. Но не всегда, на отдельных эндпоинтах обязательна передача в теле запроса.

Так же при авторизации на сайте вам выдается `xsrf` токен, он используется во всех запросах, отправляемых через `XMLHttpRequest`...

Для решения капчи нужен `captchaState`. Его возвращают некоторые эндпоинты сайта к которым обращаются через API или ссайта через `XMLHttpRequest` с 403 кодом ошибки. API его возвращает в виде ссылке. После получения `captchaKey` мы грузим изображение `/captcha/picture?key=<captchaKey>`. Ну и далее решение капчи, `captchaState` и `captchaKey` отправляются на POST-запросом на `/account/captcha` для API или эднопоинт, с которого пришла ошибка (так происходит при авторизаии)...

Самым сложным был "взлом" процесса авторизации. Мне пришлось два часа лазать искать как `loginTrustFlags` генерируются для "подписи" данных отправляемых при авторизации. Для этого мне пришлось во вкладке отладчика браузера `Sources` оредактировать скрипты на сайте, вставив в нужные места `console.log`/`console.dir`/`console.table` перед `debugger;` (для этого нужно выбрать директорию для синхронизации, тогда станет доступна возможность редактировать скрипты "прямо на сайте"). Там на странице входа из объекта с `redirectConfig` берется `loginTrustFlagsSecret`. В нем содержится публичный сертификат, которым шифруется такой JSON:

```js
{"emailOrPhone":{"paste":false,"suggest":true},"ts":Date.now()}
```

По названиям полей несложно догадаться, что там указывается был ли логин вставлен в поле или выбран из выпадающего списка при вводе. Боты, которые работают через Headless Chromium обычно ничего не вставляют и не выбирают из выпадающего списка, а "печатают"...

При авторизацию по паролю такое шифруется:

```json
{"password":{"suggest": false,"paste": false},"ts":...}
```

Далее этот объект пропускается через `JSON.stringify` и шифруется с помощью публичного ключа. Используется ассиметричное шифрование `RSA-OAEP` с хешированием `SHA-256` и кодированием в base64. Без этой подписи запроса авторизоваться не получится.

Без расстановки контрольных меток быстро данную функцию шифрования можно найти так: жмем `Ctrl-Shift-F` во вкладке `Sources` и вводим `await crypto[`, ниже будет что-то типа:

```js
// С каждой версией фронтенда имена переменных меняются
const _0x3cd982 = {
  ..._0x334204,
  // 'ts': Date['now']()
  '\x74\x73': Date[_0x50c3ac(0x13f, '\x51\x47\x76\x23')](),
};

// Добавляем и смотрим что шифруется в trustLoginFlags...
console.log('trust login: %o', _0x3cd982);
```

Большинство эндопоинтов шифрует лишь JSON с таймстемп наподобии такого: `{"ts":1791234567890}`. Я думаю, что кроме `ts` там обязательных полей нет.

В принципе больше нечего рассказать...

### Запросы к API через CLI

Для тестирования запросов к API используйте команду `call-api`. Если запросы к сайту можно прямо консоли из браузера выполнять, то для работы с API пришлось придумать эту операцию.

Эта команда вместе с `jq` для обработки JSON — основа для Bash-скриптинга, когда не хватает основного функционала и нет желания писать на питоне, а так же изучения самого API сайта.

Пример поиска работодателей:

```bash
$ hh-applicant-tool call-api /employers text="IT" only_with_vacancies=true | jq -r '.items[].alternate_url'
https://hh.ru/employer/1966364
https://hh.ru/employer/4679771
...
```

Синтаксис `call-api` немного похож на `httpie` или `curlie`:

```sh
hh-applicant-tool call-api [{GET|POST|PUT|DELETE}] <endpoint> [<key=value> ...]
```

- Если используется метод `GET` (исп-ся когда метод опущен) или `DELETE`, то параметры будут переданы как query string. Во всех остальных случаях параметры передаются как `application/x-www-form-urlencoded` в теле запроса.
- Если первым аргументом после endpoint передать JSON внутри `{}`, то на сервер отправится запрос с Content-Type `application/json` и телом в JSON. Эндпоинтов, работающих с JSON — считанные единицы. Но они есть... Я, правда, не могу вспомнить хотя бы один как называется, но помню, что был.
- Флаг `-j` принудительно выполняет запрос с телом JSON:

  ```sh
  # Отправит POST-запрос с `{"foo":"bar","baz":42}` в теле и с `Content-Type: application/json` в заголовках
  hh-applicant-tool api post -j /endpoint foo=bar baz=42
  ```

  > api — это алиас call-api

При ошибках API в `$?` будет 1.

Те такое работает:

```sh
$ hh-applicant-tool api post /test foo=bar &>/dev/null || echo "Ошибка запроса\!"
Ошибка запроса!
```

Для поиска вакансий по региону в `apply-vacancies` нужно указать параметр `area`. Можно его указывать как для страны (каз - 40, бел - 2238), так и отдельного города (мск - 1).

Пример поиска `area id` по стране и названию:

```sh
$ hh-applicant-tool api /areas | jq -r '.[] | select(.name == "Беларусь") | .. | objects | select(.name == "Барановичи")'
{
  "id": "2239",
  "parent_id": "2233",
  "name": "Барановичи",
  "areas": [],
  "utc_offset": "+03:00",
  "lat": 53.16592,
  "lng": 29.00806
}
```

Так же у меня замечание к принимаемым правкам. Например, есть клиенты HH API и OpenAI API, у них должны быть похожие "интерфейсы", те и там и там использоваться `delay`, `timeout`, `connect_timeout`. И тот и другой ничего не должны знать о классах, которых их используют, как те работают... Они должны быть максимально изолированы, но при этом подчиняться принципу единообразия какого-то... И не надо дергать методы экземпляров классов, начинающиеся с подчеркивания, они скрыты чтобы ничего не сломать, так же не надо модифицировать экземпляры на лету, устанавливая им атрибуты через `setattr`, а потом еще лезть в код, гадить, ставя проверку на `gettatr` с попыткой дернуть атрибут неизвестно кем и зачем установленный... Такую нейродрисню я принимать не буду, я заебался ее чистить. Тут код и так "мягко" говоря не идеален, но написать хуже этого — это "талант". Нужно стремиться к простоте, чем проще код, тем меньше в нем багов. Так же не надо перехватывать все возможные ошибки: любая заглушенная ошибка — это потенциальный баг. Например, если пользователь передал какую-то хуйню вместо валидных данных, то пусть приложение падает ровно в том месте, где эти данные требуются. Идиоты могут ввести что угодно в приступах безумия, все не предусмотреть.

Как пример могу привести:

```python
info = {
    "resume_skills": "",
    "resume_about": "",
    "resume_experience": "",
}
if not resume_id:
    return info

try:
    full_resume = self.api_client.get(f"/resumes/{resume_id}")
except Exception as e:
    logger.warning(f"Не удалось получить полное резюме: {e}")

```

Это фрагмент из функции, которая получает плейсхолдеры для подстановки в сопроводительные и промпты... Вот мы передали в эту функцию идентификатор резюме в надежде получить поля из него, а она вместо того чтобы упасть, потому как их не может получить вернет пустые значения, которые потом будут использоваться при отправке отклика... Отклик НЕ ДОЛЖЕН происходить, если невозможно получить какие-то важные данные!

Та же самая "логика" была с оценкой подходит ли вакансия или нет: мы не смогли получить полное описание вакансии, а давайте все равно считать ее подходящей! Ну у человека явные психические отклонения или он просто не спал долго, когда такой бред писал... Ну или это нагенерировал нейродурак, которому до пизды... Он не понимает как работает приложение, он угадывает токены... Так что примите к сведению.

Идиотию типа фильтров `heavy`, `light` и прочую поеботу я выбросил. Не надо генерировать промпты внутри. Если хочется сравнивать свое охуенное срИзюме на 10 листов с требованиями, сгенерированными тупой пиздой какой-то нейронкой (а потому к реальности не имеющее отношение, потому как вместо Vue на фронте какой Angular.js, а пизде нейронка высрала что-то релевантное, что делает все эти ебанутые идеи с хуии-фильтрациями какой-то бессмыслицей), то заводите плейсхолдеры типа `%(vacancy_full_description)s`, и используйте их у себя в шаблонах, которые задаются в конфигах, НЕ ПЛОДИТЕ ЛИШНИЕ СУЩНОСТИ, не вводите лишние переменные, флаги и настройки, если хватает существующих, и грузите это полное описание ТОЛЬКО ЕСЛИ ЕСТЬ ДАННЫЙ ПЛЕЙСХОЛДЕР, другие пользователи не должны страдать из-за чужих "гениальных" идей, вводя ебаную капчу в ручном режиме, потому как эндпоинт загрузки полного описания вакансии кидает ее гарантированно. Не надо так же дефолтными делать промпты подходящие только для вас (можно только для меня, но я таким не страдаю).

Во второй версии я вычистил проект от всего говна, скопившегося за годы, удалил около 10.000 строк... Но функционал от этого, если и изменился, то в лучшую сторону — появился вот автоответчик, все промпты через конфиг задаются... В общем просьба держать код в чистоте.

### Интеграция и использование в скриптах

Если хотите использовать `hh-applicant-tool` в своих скриптах, то можно это сделать так:

```python
from hh_applicant_tool import HHApplicantTool

tool = HHApplicantTool()
print(tool.api_client.get('/me'))
```

Команды тоже можно вызывать:

```python
>>> from hh_applicant_tool import HHApplicantTool
>>> HHApplicantTool().run(["auth", "v.pupkin@mail.ru"])
```

Команда в случае успеха возвращает `0` или `None`. При ошибках возвращает код > `0`. `130` - это прерывание пользователем. Остальные - `1` кроме `print_help` (`2`).

Если у кого есть желание, то напишите веб-морду для hh-applicant-tool — команду, которая запускает веб-сервер для управления рассылками. Так можно было бы через докер ими управлять. Капчу можно через какую шину ловить.

## Изменения между версиями

До первой утилита работала только в Linux. Когда я декомпилировал приложение, то я зная, как работает OAuth, открыл ссылку в браузере, подтвердил авторизацию, и меня перекинуло на ссылку с протоколом `hhandroid://`, содержающую код авторизации, необходимый для получения токенов. Я пробовал в ссылку для редиректа (параметр) подставлять `http://localhost`, но редирект работал только на тот протокол, который не обрабатывался браузером. В Linux можно назначить обработчик кастомного протокола. Я придумал такую хитрость, что ссылку эту для редиректа, просто писал в сокет, который открывал socat, а сокет этот случшал локальный сервер, который получив ссылку с кодом, завершал авторизацию. Оно работало, но для меня. Потом мне начали какие-то додики писать типа почему у меня твоя утилита в WSL не работает и тп... Изначально я просто знакомому показал свой аналоговнетный скрипт, а он его своим знакомым, и как-то пошло-поехало... Мне было похуй, но потом, я подумал, что пиар лишним не бывает. Так для авторизации был встроен QT, который позволял регистрировать кастомные протоколы. Теперь утилита могла работать на любой платформе, которая поддерживала QT... Потом я захотел запускать утилиту на сервере, но на сервере не получится заупустить окошко с браузером, так PyQt заменил playwright, который уже запускал Headless Chromium, а так же автоматизировать его, вводя данные в поля и нажимая кнопки... Тогда же авторизация начала работать из терминала, ты передавал логин и пароль через аргументы, а потом в фоне запускался браузер, нажимал по кнопкам за тебя... И все работало, пока вайбкодеры своими правками, которые я все мержил, в итоге все нахуй не сломали... Тогда я и решился разобраться в том как работает все в браузере, куда какие запросы шлются, и так была рождена вторая версия, которую фактически является первой нормальной.

Во второй версии в сравнении с первой официальной произошли следующие изменения:

- удалено примерно 10.000 строк кода, большая часть которого была прислана нейропейсателями, и представляла из себя компиляцию хуеты и бреда, поэтому их выпиливание на функционал не повлияло
- удален слой для работы с базой, утилита в ней больше ничего не хранит, так как этим функционалом никто не пользовался
- выпилен из зависимостей headless-chromium. раньше для прохождения авторизации и решения капчи запускался в фоне браузер, хотя вы его и не видели. я нашел способ авторизации и решения капчи в обход браузера.
- переписана ранее бесполезная операция `reply-chats`. теперь это полноценный автоответчик для чатов.
- теперь утилита хуИИ-first. без оного невозможно отвечать в чатах, а вот рассылка откликов может работать и без него, но в сопроводительных будет однотипный текст, где только подставляются ваше имя и названия компании, вакансии...
- настройки всех промптов вынесены в конфиг
- конфиг сменил формат с json на toml, так как в последнем есть комментарии и строки типа таких:
  ```toml
  # Я комментарий
  setting_name = """
  Тут можно писать целые рассказы

  Это все считается одной строкой...
  """

- все промпты вынесены в конфиг, а флаги для их задания удалены. передавать километровые строки во флагах — это идиотская идея
- токены вынесены из конфига, так как когда мы грузим конфиг, то комментариев в нем нет, и, следовательно, когда сохраняем, их там не будет, те сохранение токенов там затрет комменты, а они часто нужны
