## Особенности и функционал

> [!IMPORTANT]
> Tool — утилита, это программа не имеющая GUI/TUI, те данное ПО задумывалось
> строго для работы в сосноли/терминале, а поэтому все ее гуевые фишки
> существуют постольку-поскольку (Alacritty не поддерживает вывод графики).
> Её предназначение крутиться где-то в автозапуске, не отвлекая на себя
> внимание. Написал раз конфиг, запустил и забыл.

- 🐍 Утилита написана на Python, а значит может быть запущена на любой системе, куда его можно установить (Windows, Linux, Mac и даже на Android)
- 🤖 Поддержка ИИ (ChatGPT, Claude и все что работает через OpenAI API Specification)
- 🔄 Авто-поднятие резюме
- 📤 Рассылка откликов с генерацией сопроводительных и решением тестов (может работать без нейронки)
- 🧩 Автоматическое распознание капчи
- 📧 Дополнительная рассылка писем на Email работодателям с просьбой рассмотреть резюме
- 💬 Автоответчик в чате с работодателем с ответом на вопросы (если при отклике нет теста, то тест гарантированно будет в чате) в тч с вариантами (кнопки)
- 👥 Поддержка нескольких аккаунтов через профили
- 🛡️ Запуск прямо с вашего устройства с эмуляцией работы через браузер и официальное Android-приложение (в headless-режиме он не запускается, используется лишь "стандартная" библиотека `requests` для всех запросов). Для HH вы выглядите как обычный пользователь, что сводит к минимуму риск блокировки (в отличие от сторонних веб-сервисов, чьи аккаунты быстро банят)
- 🔒 Данные хранятся локально, никаких скрытых зондов и отправки данных на сторонние сервера, а значит ваши данные не утекут в результате взлома или не будут переданы различным мошенникам
- ⚙️ В отличии от различных сервисов и других решений, все промпты можно прописать самому. Универсальных решений не бывает, а однотипные сервисные ответы палятся как уши зайца, торчащие из кустов...
- 🖥️ Может запускаться на сервере. В отличии от сторонних реализаций не использует Headless Chromium, поэтому потребляет минимальное количество ресурсов, что критично для бюджетных серверов. Хромиум сильно грузит процессор, потребляет сотни мегабайт оперативной памяти при открытии hh и требует 1-2 гигабайт свободного места. Так что утилите хватит и VDS за пару сотен.
- 📖 Открытый исходный код

## Установка

Утилиту можно установить из `PyPi` или скачать из репозитория. Из остальных мест ее скачивать не рекомендуется.

Установка:

```bash
# Стандартный pip (в Linux только в виртуальное окружение получится установить)
$ pip install hh-applicant-tool

# Но лучше использовать pipx
$ pipx install hh-applicant-tool

# Последнюю версию можно установить через git
$ pipx install "git+https://github.com/s3rgeym/hh-applicant-tool"

# Для обновления до новой версии
$ pipx upgrade hh-applicant-tool
```

pipx добавляет исполняемый файл `hh-applicant-tool` в `~/.local/bin`, делая эту команду доступной. Путь до `~/.local/bin` должен быть в `$PATH` (в большинстве дистрибутивов он добавлен).

Использование виртуальных окружений в Linux/Mac:

```sh
mkdir -p ~/.venvs
python -m venv ~/.venvs/hh-applicant-tool
# Это придется делать постоянно, чтобы команда hh-applicant-tool стала доступна
.  ~/.venvs/hh-applicant-tool/bin/activate
pip install hh-applicant-tool
```

Отдельно я распишу процесс установки в **Windows** в подробностях:

- Для начала поставьте последнюю версию **Python 3** любым удобным способом.
- Запустите **PowerShell** (не `CMD.EXE`, блять, а именно поверщель) от Администратора и выполните:

  ```ps
  Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy Unrestricted
  ```

  Данная политика разрешает текущему пользователю (от которого зашли) запускать скрипты. Без нее не будут работать виртуальные окружения.

Далее можно поставить `pipx` и вернуться к инструкции вверху раздела:

- Всё так же от администратора выполните:

  ```ps
  python -m pip install --user pipx
  ```

  А затем:

  ```ps
  python -m pipx ensurepath
  ```

- Перезапускаем Terminal/Powershell и проверяем:

  ```ps
  pipx -h
  ```

С использованием вирт. окружений:

- Создайте и активируйте виртуальное окружение:

  ```ps
  PS> python -m venv hh-applicant-venv
  PS> .\hh-applicant-venv\Scripts\activate
  ```

- Поставьте все пакеты в виртуальное окружение `hh-applicant-venv`:

  ```ps
  (hh-applicant-venv) PS> pip install hh-applicant-tool
  ```

- Проверьте, работает ли оно:

  ```ps
  (hh-applicant-venv) PS> hh-applicant-tool -h
  ```

- В случае неудачи вернитесь к первому шагу.
- Для последующих запусков сначала активируйте виртуальное окружение.

## Авторизация

Авторизация по коду:

```bash
$ hh-applicant-tool authorize 79012345678
📱 Введите полученный код из SMS: 1488
🎉 Авторизация прошла успешно!
```

Если при авторизации указать email, то код придет на него.

Для авторизации по паролю передайте вторым аргументом пароль (после регистрации его нужно установить).

> Если у вас есть еще профиль работодятла или овчар-менеХера, то тип авторизации
> принудительно будет сменен на соискателя (applicant)

Проверка авторизации:

```bash
$ hh-applicant-tool whoami
🆔 27405918 Кузнецов Андрей Владимирович [ 📄 1 | 👁️ +115 | ✉️ +28 ]
```

В случае успешной авторизации токены будут сохранены в [auth.json](#authjson):

Токен доступа выдается на две недели. <s>Для его обновления нужно выполнить:

```bash
hh-applicant-tool refresh-token
```

</s> Он обновляется автоматически.

Помните, что у `refresh_token` тоже есть время жизни, поэтому может потребоваться полная авторизация, если долго не запускать утилиту + время жизни cookies может быть меньше времени жизни токенов, поэтому часть функционала, требующая авторизации на сайте может отваливаться, поэтому в любой непонятной ситуации следует попробовать авторизоваться по-новой.

## Описание команд

Примеры команд:

```bash
# Общий вид команды
$ hh-applicant-tool [глобальные флаги] [операция] [флаги самой операции]


# Справка по глобальным флагам и список операций
$ hh-applicant-tool -h

# Справка по операции
$ hh-applicant-tool authorize -h

# Авторизация по одноразовому коду, где username — телефон или email
$ hh-applicant-tool authorize <username>

# Авторизация по паролю
$ hh-applicant-tool authorize <username> <password>

# Авторизация с использованием другого профиля
# В дальнейшем для вызова всех операций надо профиль передавать,
# либо установить временную окружения
$ hh-applicant-tool --profile profile123 authorize

# Рассылаем отклики
$ hh-applicant-tool apply-vacancies

# Для тестирования поисковой строки и других параметров, используйте --dry-run.
# С ним отклики не отправляются, а лишь выводятся сообщения
$ hh-applicant-tool -vv apply-vacancies --search "Python программист" --total-pages 1 --dry-run

# Фильтруем вакансии по исключаемым словам (fullstack, junior, php и т.п.)
# Вакансии, не прошедшие фильтр, добавляются в черный список
$ hh-applicant-tool apply-vacancies --search "Python Backend" --excluded-filter "fullstack,junior,php,java" --dry-run

# Поднимаем резюме
$ hh-applicant-tool update-resumes

# Запускаем автоответчик в чате (если настроен openai)
$ hh-applicant-tool reply-chats

# Просмотр лога в реальном времени
$ hh-applicant-tool log -f

# Посмотреть содержимое конфига
$ hh-applicant-tool config

# Редактировать конфиг в стандартном редакторе
$ hh-applicant-tool config -e

# Установить значение в конфиге, например, socks-прокси
# УЧТИТЕ, ЧТО ПРИ ТАКОМ СПОСОБЕ ИЗМЕНЕНИЯ КОНФИГА, ИСЧЕЗНУТ ВСЕ КОММЕНТАРИИ В НЕМ!!!
$ hh-applicant-tool config openai.default.proxy_url socks5h://localhost:1080

# Вывести значение из конфига
$ hh-applicant-tool config openai.default.proxy_url

# Удалить значение из конфига
# Эта операция тоже форматирует конфиг, удаляя из него комментарии
$ hh-applicant-tool config -d openai.default.proxy_url

# Чистим отказы
$ hh-applicant-tool clear-negotiations
```

AI (ChatGPT и тп) будет использоваться автоматически, если в [конфиге](#конфигурационный-файл) заданы настройки для `openai`.

Глобальные флаги:

| Флаг                                                                                               | Описание                                                                                             |
| -------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `-v`                                                                                               | используется для вывода отладочной информации. Два таких флага, например, выводят запросы к **API**. |
| `-c <path>`                                                                                        | путь до каталога, где хранятся конфигурации.                                                         |
| `--profile <profile-id>`                                                                           | можно указать профиль, данные которого будут храниться в подкаталоге. |

## Капча

Если вызов какого-то метода API генерирует ошибку капчи, то она перехватывается, а далее происходит следующее:

- при включенном и настроенном AI, если не передан дополнительно
  `--captcha-manual`, капча будет распознаваться нейронкой, причем модель должна быть с поддержкой vision (например, в `llama3:latest` ее нет)
- иначе:
  - капча отображается в терминале, если есть флаги `--use-kitty`/`--use-sixel` с именами используемых протоколов для отображения изображений (первый поддерживает даже Windows Terminal)
  - если не поддерживается графика, то капча принудительно выводится в терминал через `sixel`
  - в противном случае капча будет отображена через всплывающее окно `tkinter`

Перехват капчи я сделал глобальным прямо как в их мобильном приложении, где они обработчик 403 ошибки с капчей сделали через intercept okhttp3 (напоминаю, что Java — говно), где они ловят ошибку и показывают капчу в webview. У меня только webview нет как и потрохов браузера...

Особенность API хх.сру является то, что при достижении некоторых лимитов, причем, у каждого эндпоинта они свои, или же, например, если ему не нравится user-agent (поэтому не меняйте дефолтный), он может на все попытки решить капчу отдавать 403, те не засчитывать правильные решения. Это сделано чтобы боты бесконечно сливали токены. Экспериментально установить лимиты сложно, потому как они постоянно меняются.

## Запуск через Docker

Это самый простой способ запуска и использования утилиты, требующий скопипастить 5 команд. Если не работает стандартная установка, используйте его.

Для начала нужно установить `docker` и `docker-compose`:

```sh
sudo apt install docker.io docker-compose-v2
```

Выкачиваем репозиторий и переходим в каталог:

```sh
git clone https://github.com/s3rgeym/hh-applicant-tool
cd hh-applicant-tool
```

> [!IMPORTANT]
> Команды с docker compose нужно запускать строго, находясь в данном каталоге!

Теперь авторизуемся:

```sh
# Чтобы ввести капчу в терминале укажите флаги --use-sixel/-s или --use-kitty/-k
# Это названия протоколов, которые исп-ся терминалом для отображения изображений
# Sixel поддерживается большинством терминалов
# А вот Windows Terminal поддерживает только Kitty
docker compose run --rm -it hh_applicant_tool -vv authorize
```

Все аргументы, переданные после имени сервиса, попадают напрямую в `hh-applicant-tool`.

Подробно про авторизацию можно почитать [здесь](#авторизация).

При успешно авторизации будет создан `auth.json`:

```sh
$ cat config/auth.json
{"token":{"access_token":"USERXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX","refresh_token":"USERXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX","access_expires_at":1790000000}}
```

После авторизации нужно настроить AI в файле `config/config.toml`.

Далее запускаем сервисы:

```sh
docker compose up -d
```

Описание севисов:

- `apply_vacancies` — рассылает отклики со всех опубликованных резюме раз в сутки.
- `update_resumes` — поднимает ВСЕ резюме раз в 4 часа.
- `reply_chats` — автоответчик в чат, с проверкой чатов раз в 5 минут.

Просмотр логов:

```sh
docker compose logs -f
```

Чтобы прекратить просмотр логов, нажмите `Ctrl-C`.

Запущенные сервисы докер стартуют автоматически после перезагрузки и перезапускаются при падении. Остановить их можно выполнив:

```sh
docker compose down
```

Чтобы обновить утилиту, в большинстве случаев достаточно в каталоге выполнить:

```sh
git pull
```

В редких случаях нужно пересобрать все:

```sh
docker compose up -d --build
```

Профиль, под которым работает утилита, можно задать переменной окружения `HH_PROFILE_ID`.

[Команды](#описание-команд) можно потестировать в контейнере:

```sh
docker compose run --rm -it hh_applicant_tool whoami
```

## Настройки и данные приложения

Настройки и данные приложения хранятся по следующим путям:

| OS          | Путь                                                     |
| ----------- | -------------------------------------------------------- |
| **Windows** | `C:\Users\%username%\AppData\Roaming\hh-applicant-tool\` |
| **macOS**   | `~/Library/Application Support/hh-applicant-tool/`       |
| **Linux**   | `~/.config/hh-applicant-tool/`                           |

### Конфигурационный файл

Конфигурационный называется `config.toml`. Он содержит основные настройки.

[TOML](https://ru.wikipedia.org/wiki/TOML) идеально подходит для хранения конфигураций, так как поддерживает мультистроки и комментарии в отличии от старого формата JSON, который разве что для роботов подходит.

Самый быстрый способ открыть конфиг в стандартном редакторе:

```bash
hh-applicant-tool config -e
```

Путь до него можно найти так:

```bash
hh-applicant-tool config -p

# Можно сразу открыть в любимом редакторе
code $(hh-applicant-tool config -p)
```

> Учтите, что настройки принадлежат той секции, чьи квадратные скобки выше
> ближе, те какой-то порядок надо соблюдать

Формат файла:

```toml
[general]
# Прокси для запросов к hh.ru
# Приоритет: флаг --proxy-url, затем этот параметр, затем переменные окружения HTTP_PROXY / HTTPS_PROXY
proxy_url = "http://user:pass@127.0.0.1:8080"

# Вместо дефолтного https://hh.ru впишите свой
base_url = "https://rabota.by"
# FireFox
user_agent = "Mozilla/5.0 (Windows NT 10.0; Win64; x64; rv:157.0) Gecko/20100101 Firefox/157.0"
captcha_lang = "RU"

# ---------------------------------------------------------------------------
# Команда apply-vacancies (apply, apply-similar)
#
# Во всех шаблонах ниже подстановка идёт в формате %(name)s, поэтому знак
# процента нужно писать как %%. Конструкция {а|б} выбирает случайный вариант.
#
# Общие плейсхолдеры apply-vacancies (доступны во всех шаблонах этой команды,
# кроме промптов теста):
#   first_name    - имя пользователя
#   last_name     - фамилия
#   email         - email пользователя
#   phone         - телефон
#   resume_hash   - идентификатор резюме
#   resume_title  - название резюме
#   resume_url    - ссылка на резюме
#   vacancy_name  - название вакансии
#   vacancy_url   - ссылка на вакансию
#   employer_name - название работодателя
# ---------------------------------------------------------------------------

# Шаблон сопроводительного письма
# Плейсхолдеры: общие плейсхолдеры apply-vacancies
cover_letter = """
{Здравствуйте|Добрый день}, меня зовут %(first_name)s.

{Прошу|Предлагаю} рассмотреть {мою кандидатуру|мое резюме «%(resume_title)s»} на вакансию «%(vacancy_name)s».

У меня есть релевантный опыт работы и интерес к задачам вашей компании.

С уважением,
%(first_name)s
"""

# Промпт для генерации сопроводительного письма
# Плейсхолдеры: общие плейсхолдеры apply-vacancies
# Системный промпт задаётся в [openai.cover_letter].system_prompt
cover_letter_prompt = """
Напиши сопроводительное письмо для отклика на вакансию %(vacancy_name)s.
"""

# Промпт AI-фильтра вакансий (--ai-filter). Модель должна ответить «да» или «нет»,
# любой непонятный ответ считается «да».
# Плейсхолдеры: общие плейсхолдеры apply-vacancies, а также
#   resume_skills      - навыки из резюме через запятую (skill_set)
#   resume_about       - блок «О себе» из резюме
#   resume_experience  - опыт работы списком: компания, должность, период, описание
#   vacancy_key_skills - ключевые навыки вакансии через запятую
#   vacancy_description - описание вакансии без HTML-тегов
# Системный промпт задаётся в [openai.vacancy_filter].system_prompt
ai_filter_prompt = """
Резюме кандидата:
Должность: %(resume_title)s
Навыки: %(resume_skills)s

Вакансия: %(vacancy_name)s
Ключевые навыки: %(vacancy_key_skills)s
Описание: %(vacancy_description)s

Подходит ли эта вакансия кандидату?
"""

# Промпты для решения тестов при откликах
# Системный промпт задаётся в [openai.test_solver].system_prompt
#
# Выбор варианта ответа. Плейсхолдеры:
#   question - текст вопроса
#   options  - варианты, по одному на строку в формате «ID: текст»
test_choice_prompt = """
Вопрос: %(question)s
Варианты:
%(options)s
Выбери правильный вариант. Ответь только его ID.
"""

# Свободный текстовый ответ. Плейсхолдеры:
#   question - текст вопроса
test_text_prompt = """
Вопрос: %(question)s
Дай краткий ответ. Только текст ответа.
"""

# Тема и текст письма, отправляемого на email компании (--send-email)
# Плейсхолдеры: общие плейсхолдеры apply-vacancies
apply_mail_subject = "{Отклик|Резюме} на вакансию %(vacancy_name)s"

# Поддерживается HTML. Значения плейсхолдеров экранируются автоматически
apply_mail_body = """
<p>{Здравствуйте|Добрый день}, {прошу рассмотреть|пожалуйста рассмотрите} мое резюме %(resume_url)s на вакансию %(vacancy_name)s.</p>

"""

# ---------------------------------------------------------------------------

# Промпты для команды reply-chats
# Эти параметры должны находиться в корне конфигурации, до первой секции TOML.
#
# Доступные плейсхолдеры (одни и те же для обоих промптов и для system_prompt
# из [openai.reply_chat]):
#   first_name, last_name, email, phone - данные пользователя
#   vacancy_name         - название вакансии

#   vacancy_compensation - зарплата в вакансии (пусто, если не указана)
#   employer_name        - название работодателя
#   contact_name         - имя автора последнего сообщения
#   resume_title         - название резюме
#   resume_salary        - зарплатные ожидания из резюме
#   resume_skills        - навыки из резюме
#   resume_experience    - опыт работы (до 3 последних мест)
#   reply_to_message     - сообщение работодателя, на которое нужно ответить
#   options              - варианты ответа-кнопки, по одному на строку с «- »
#   history              - история переписки (только в reply_chat_user_prompt)
#   message_count        - число сообщений в истории (только в reply_chat_user_prompt)
# В reply_chat_options_prompt history и message_count пустые.

reply_chat_user_prompt = """
Ты помогаешь отвечать на сообщения работодателей на hh.ru.

Информация о вакансии:
- Название: %(vacancy_name)s
- Зарплата: %(vacancy_compensation)s

%(reply_to_message)s

%(history)s

# Ответ должен совпасть с одним из вариантов, иначе сообщение не отправляется
reply_chat_options_prompt = """
Сообщение, на которое нужно ответить:
%(reply_to_message)s
```

Часть настроек скрыта.

Практически все настройки имеют дефолтное значение кроме настроек OpenAI. Это название стандарта через который взаимодействуют с LLM или как их часто неправильно называют AI.

Минимальный конфиг может выглядеть примерно так:

```toml
[general]
# Тут юзер-агент вашего любимого браузера для посещения hh.ru (у клиента API юзер-агент генерируется)
# Дефолтный очень быстро устаревает, и сайт может начать вас считать подозрительным
user_agent = "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/150.0.0.0 YaBrowser/26.8.0.0 Safari/537.36"

# свой локальный ip типа 192.168.1.100
[openai.default]
base_url = "http://localhost:11434/v1"
model = "llama3"
```

Для тестирования настроек запустить `hh-applicant-tool` с `-vv`, так в терминала будут выводиться сообщения отладки. Либо же можно посмотреть логи с помощью операции `log`.

Некоторые настройки передаются как аргумент конструктора, поэтому если увидите сообщение типа:

```sh
TypeError: ApiClient.__init__() got an unexpected keyword argument 'timeoutt'
```

Параметр `delay` в секциях `[api_client]` и `[openai.*]` работает не так как все думают:

- Допустим, у нас `delay = 0.5`
- Например, со времени предыдущего запроса к API прошло 0.3 секунды, тожда мы ждем 0.2 секунды (0.5 - 0.3)
- Если же прошло больше этого времени, перед запросом ожидание не делается

Это универсальнее rate limit'ов, так как работать будет везде, а не только там, где можно друг-другом пять запросов выполнить, а на 6 лимит сработает. Много где 5 запросов в секунду - это 5 запросов с задержкой до 200мс.

### auth.json

Хранит токены авторизации.

### cookies.txt

В `cookies.txt` хранятся куки, установленные при авторизации на сайте. Они нужны
для решения тестов при отклике на вакансию. Не редактируйте этот файл вручную.

Операция `logout` не только затирает токены, но очищает `cookies.txt`.

### Логи

В `log.txt` всегда можно посмотреть подробную информацию об ошибках. В целях безопасности токены, идентификаторы резюме и т. п. затираются. Для просмотра логов используйте операцию `log`.

### Переменные окружения

Утилита читает следующие переменные окружения:

| Переменная                    | Описание                                                                                                                               |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `CONFIG_DIR`                  | Каталог, в котором хранятся данные приложения, вместо пути по умолчанию (см. «Данные приложения»). В Docker задаётся как `/app/config` |
| `HH_PROFILE_ID`               | Имя подкаталога-профиля внутри `CONFIG_DIR` (по умолчанию `.`). Позволяет держать несколько изолированных профилей                     |
| `HTTP_PROXY` / `http_proxy`   | Прокси для HTTP-запросов к API HH, если не задан `proxy_url` в конфиге                                                                 |
| `HTTPS_PROXY` / `https_proxy` | Прокси для HTTPS-запросов к API HH; если не задан — используется HTTP-прокси                                                           |

Первые нужны для удобства в `Docker`. Последние — де факто стандарт.

## Шаблоны сообщений

При откликах доступны сл плейсхолдеры (как это на русском?) шаблонов (актуальный список см в `apply-vacancies -h`):

- **`%(vacancy_name)s`**: Название вакансии.
- **`%(vacancy_url)s`**: Ссылка на вакансию.
- **`%(employer_name)s`**: Название работодателя.
- **`%(first_name)s`**: Имя пользователя.
- **`%(last_name)s`**: Фамилия пользователя.
- **`%(email)s`**: Email пользователя.
- **`%(phone)s`**: Телефон пользователя.
- **`%(resume_title)s`**: Название резюме.
- **`%(resume_hash)s`**: Идентификатор резюме.
- **`%(resume_url)s`**: Ссылка на резюме.
- ...

Например:

```
Меня заинтересовала ваша вакансия %(vacancy_name)s. Прошу рассмотреть мою кандидатуру. С уважением, %(first_name)s %(last_name)s.
```

Плейсхолдеры можно использовать в промптах.

Вообще эта форма записи — это старые, добрые форматированные строки в Python до того как из C# притащили ASCII-вагины `{}`. С ними можно разное делать, например, `%(first_name).1s` выведет первую букву имени...

Также можно делать текст уникальным с помощью `{}`. Внутри них через `|` перечисляются варианты, один из которых будет случайно выбран:

```
Увольте того {идиота|придурка}, который придумал этот {тупой|сраный|дурацкий} вопрос.
```

В итоге получится что-то вроде:

```
Увольте того идиота, который придумал этот сраный вопрос.
```

`{}` могут быть вложенными.

Точно так же обстоят дела с решением капчи. **API** буквально нам предлагает открыть страницу с капчей в браузере, решить ее, а потом вызвать нужный метод **API** снова.

Сам сайт ХХ использует React. На каждой странице есть тег `<template id="HH-Lux-InitialState"></template>`. Внутри него заключен JSON `{"redirectConfig":....}`, в котором разделители заменены на HTML-сущности. В нем содержатся данные, необходимые для рендеринга страницы. Если нужно спарсить какие-то данные с веб-версии (у них она называется десктопной), то искать их стоит там. Там, кстати, много лишнего хранится: от ссылки на бота в Telegram для сотрудников поддержки сайт до страниц каких-то инфоцыган (этот уебанский сайт ставку сделал на зарабатывание денег на соискателях, я это осуждаю в отличии от доения тамошних работодятлов с их тупорылыми херками).

Сами эндпоинты сайта работают довольно странно. Параметры могут передавать через тело, Query String, через куки и заголовки. Но не всегда, на отдельных эндпоинтах обязательна передача в теле запроса.

Так же при авторизации на сайте вам выдается `xsrf` токен, он используется во всех запросах, отправляемых через `XMLHttpRequest`...

Для решения капчи нужен `captchaState`. Его возвращают некоторые эндпоинты сайта к которым обращаются через `XMLHttpRequest`. Либо он содержится в ссылке. Далее нужно получить `captchaKey`, послав POST-запрос без тела на эндпоинт сайта `/captcha?lang=RU` (можно указать еще `EN`). После получения `captchaKey` мы грузим изображение `/captcha/picture?key=<captchaKey>`. Ну и далее решение капчи, `captchaState` и `captchaKey` отправляются на POST-запросом на `/account/captcha`. При авторизации `captchaState` и пр могут отправляться прямо в самом запросе к эндпоинту...

Самым сложным был "взлом" процесса авторизации. Мне пришлось два часа лазать искать как `loginTrustFlags` генерируются для "подписи" данных отправляемых при авторизации. Там на странице входа из объекта с `redirectConfig` берется `loginTrustFlagsSecret`. В нем содержится публичный сертификат, которым шифруется такой JSON:


По названиям полей несложно догадаться, что там указывается был ли логин вставлен в поле или выбран из выпадающего списка при вводе. Боты, которые работают через Headless Chromium обычно ничего не вставляют и не выбирают из выпадающего списка, а "печатают"...

> При авторизацию по паролю такое шифруется: {"password":{"suggest": false,"paste": false},"ts":...}

Далее этот объект пропускается через `JSON.stringify` и шифруется с помощью публичного ключа. Используется ассимитричное шифрование `RSA-OAEP` с хешированием `SHA-256` и кодированием в base64. Без этой подписи запроса авторизоваться не получится.

Без расстановки контрольных меток быстро данную функцию шифрования можно найти так: жмем `Ctrl-Shift-F` во вкладке `Sources` и вводим `await crypto[`, ниже будет что-то типа:

```js
// С каждой версией фронтенда имена переменных меняются
const _0x3cd982 = {
  ..._0x334204,
  // 'ts': Date['now']()
  '\x74\x73': Date[_0x50c3ac(0x13f, '\x51\x47\x76\x23')](),
};

// Добавляем и смотрим что шифруется в trustLoginFlags...
console.log('trust login: %o', _0x3cd982);
```

Большинство эндопоинтов шифрует лишь JSON с таймстермп наподобии такого: `{"ts":1791234567890}`. Я думаю, что кроме `ts` там обязательных полей нет.

### Запросы к API через CLI

Для тестирования запросов к API используйте команду `call-api`. Если запросы к сайту можно прямо консоли из браузера выполнять, то для работы с API пришлось придумать эту операцию.

Эта команда вместе с `jq` для обработки JSON — основа для Bash-скриптинга, когда не хватает основного функционала и нет желания писать на питоне, а так же изучения самого API сайта.

Пример поиска работодателей:

```bash
$ hh-applicant-tool call-api /employers text="IT" only_with_vacancies=true | jq -r '.items[].alternate_url'
https://hh.ru/employer/1966364
https://hh.ru/employer/4679771
...
```

Синтаксис `call-api` немного похож на `httpie` или `curlie`:

```sh
hh-applicant-tool call-api [{GET|POST|PUT|DELETE}] <endpoint> [<key=value> ...]
```

- Если используется метод `GET` (исп-ся когда метод опущен) или `DELETE`, то параметры будут переданы как query string. Во всех остальных случаях параметры передаются как `application/x-www-form-urlencoded` в теле запроса.
- Если первым аргументом после endpoint передать JSON внутри `{}`, то на сервер отправится запрос с Content-Type `application/json` и телом в JSON. Эндпоинтов, работающих с JSON — считанные единицы. Но они есть... Я, правда, не могу вспомнить хотя бы один как называется, но помню, что был.
- Флаг `-j` принудительно выполняет запрос с телом JSON:

  ```sh
  # Отправит POST-запрос с `{"foo":"bar","baz":42}` в теле и с `Content-Type: application/json` в заголовках
  hh-applicant-tool api post -j /endpoint foo=bar baz=42
  ```

  > api — это алиас call-api

При ошибках API в `$?` будет 1.

Те такое работает:

```sh
$ hh-applicant-tool api post /test foo=bar &>/dev/null || echo "Ошибка запроса\!"
Ошибка запроса!
```

Для поиска вакансий по региону в `apply-vacancies` нужно указать параметр `area`. Можно его указывать как для страны (каз - 40, бел - 2238), так и отдельного города (мск - 1).

Пример поиска `area id` по стране и названию:

```sh
$ hh-applicant-tool api /areas | jq -r '.[] | select(.name == "Беларусь") | .. | objects | select(.name == "Барановичи")'
{
  "id": "2239",
  "parent_id": "2233",
  "name": "Барановичи",
  "areas": [],
  "utc_offset": "+03:00",
  "lat": 53.16592,
  "lng": 29.00806
}
```

- `git clone ...`
- `poetry install .`
- **poetry** можно установить через **pipx**
- в дальнейшем можно запускать утилиту так `poetry run hh-applicant-tool authorize`

Утилита использует систему плагинов. Все они лежат в [operations](https://github.com/s3rgeym/hh-applicant-tool/tree/main/src/hh_applicant_tool/operations). Модули, расположенные там, автоматически добавляются как доступные команды. За основу для своего плагина можно взять [whoami.py](https://github.com/s3rgeym/hh-applicant-tool/tree/main/src/hh_applicant_tool/operations/whoami.py).

Для публикации новой версиии утилиты на `PyPi` нужно указывать версию. Она указывается в `pyproject.toml`. Когда делаете `Pull Request`, то увеличивайте эту версию на единичку (при малозначительных изменениях — последнее число).

Так же у меня замечание к принимаемым правкам. Например, есть клиенты HH API и OpenAI API, у них должны быть похожие "интерфейсы", те и там и там использоваться `delay`, `timeout`, `connect_timeout`. И тот и другой ничего не должны знать о классах, которых их используют, как те работают... Они должны быть максимально изолированы, но при этом подчиняться принципу единообразия какого-то... И не надо дергать методы экземпляров классов, начинающиеся с подчеркивания, они скрыты чтобы ничего не сломать, так же не надо модифицировать экземпляры на лету, устанавливая им атрибуты через `setattr`, а потом еще лезть в код, гадить, ставя проверку на `gettatr` с попыткой дернуть атрибут неизвестно кем и зачем установленный... Такую нейдродрисню я принимать не буду, я заебался ее чистить. Тут код и так "мягко" говоря не идеален, но написать хуже этого — это "талант". Нужно стремиться к простоте, чем проще код, тем меньше в нем багов. Так же не надо перехватывать все возможные ошибки: любая заглушенная ошибка — это потенциальный баг. Например, если пользователь передал какую-то хуйню вместо валидных данных, то пусть приложение падает ровно в том месте, где эти данные требуются. Идиоты могут ввести что угодно в приступах безумия, все не предусмотреть.

Как пример могу привести:

```python
info = {
    "resume_skills": "",
    "resume_about": "",
    "resume_experience": "",
}
if not resume_id:
    return info

try:
    full_resume = self.api_client.get(f"/resumes/{resume_id}")
except Exception as e:
    logger.warning(f"Не удалось получить полное резюме: {e}")
    return info
```

Это фрагмент из функции, которая получает плейсхолдеры для подстановки в сопроводительные и промпты... Вот мы передали в эту функцию идентефикатор резюме в надежде получить поля из него, а она вместо того чтобы упасть, потому как их не может получить вернет пустые значения, которые потом будут использоваться при отправке отклика... Отклик НЕ ДОЛЖЕН происходить, если невозможно получить какие-то важные данные!

Та же самая "логика" была с оценкой подходит ли вакансия или нет: мы не смогли получить полное описание вакансии, а давайте все равно считать ее подходящей! Ну у человека явные психические отклонения или он просто не спал долго, когда такой бред писал... Ну или это нагенерировал нейродурак, которому до пизды... Он не понимает как работает приложение, он угадывает токены... Так что примите к сведению.

Идиотию типа фильтров `heavy`, `light` и прочую поеботу я выбросил. Не надо генерировать промпты внутри. Если хочется сравнивать свое охуенное срИзюме на 10 листов с требованиями, сгенерированными тупой пиздой какой-то нейронкой (а потому к реальности не имеющее отношение, потому как вместо Vue на фронте какой Angular.js, а пизде нейронка высрала что-то релевантное, что делает все эти ебанутые идеи с хуии-фильтрациями какой-то бессмыслицей), то заводите плейсхолдеры типа `%(vacancy_full_description)s`, и спользуйте их у себя в шаблонах, которые задаются в конфигах, НЕ ПЛОДИТЕ ЛИШНИЕ СУЩНОСТИ, не вводите лишние переменные, флаги и настройки, если хватает существующих, и грузите это полное описание ТОЛЬКО ЕСЛИ ЕСТЬ ДАННЫЙ ПЛЕЙСХОЛДЕР, другие пользователи не должны страдать из-за чужих "гениальных" идей, вводя ебаную капчу в ручном режиме, потому как эндпоинт загрузки полного описания вакансии кидает ее гарантированно. Не надо так же дефолтными делать промпты подходящие только для вас (можно только для меня, но я таким не страдаю).

Во второй версии я вычистил проект от всего говна, скопившегося за годы, удалил около 10.000 строк... Но функционал от этого, если и изменился, то в лучшую сторону — появился вот автоответчик, все промпты через конфиг задаются... В общем просьба держать код в чистоте.

### Интеграция и использование в скриптах

Если хотите использовать `hh-applicant-tool` в своих скриптах, то можно это сделать так:

```python
from hh_applicant_tool import HHApplicantTool

tool = HHApplicantTool()
print(tool.api_client.get('/me'))

# Какую-то вспомогательную информацию можно сохранять в настройках
import datetime as dt

# Учтите, что в таком случае токены, которые могут обновиться при выполнении запросов,
# нужно сохранять вручную
tool.save_token()
```

Команды тоже можно вызывать:

```python
>>> from hh_applicant_tool import HHApplicantTool
>>> HHApplicantTool().run(["auth", "v.pupkin@mail.ru"])
```

Если же утилита интегрируется в графические приложения, то как правило должна быть возможность отменить текущую операцию:

```python
import multiprocessing as mp

from hh_applicant_tool import HHApplicantTool

def run_command(argv: list[str]):
    HHApplicantTool().run(argv)

p = mp.Process(target=run_command, args=(['apply-vacancies', ...],))
p.start()

# Убили процесс
p.terminate()

# Ждем пока не помрет
p.join()
```
